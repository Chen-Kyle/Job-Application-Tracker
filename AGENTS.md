# Project instructions

Every assistant-made change to this project must include updates to both change logs in the same task:

- `CHANGES_TECHNICAL.md`: detailed request, resulting changes, affected files, validation, and remaining limitations.
- `CHANGES.md`: concise, easy-to-read dated summary.

Use America/New_York dates and put new entries first. Apply this requirement to code, configuration, documentation, and project-instruction edits. Answers that do not change files do not need log entries. Never record secrets or personal email contents. Do not claim browser testing or external setup was completed without evidence.

Keep the table of contents in `CHANGES.md` updated with a hyperlink for every dated section.

## Commit and push

The user authorizes committing and pushing completed requested changes to `https://github.com/Chen-Kyle/Job-Application-Tracker.git` without asking again.

- Update both logs and run checks appropriate to the changes before committing.
- Review the diff and stage only changes made for the authorized work. Do not include unrelated user edits, private data, backups, tokens, or secrets.
- Use a clear commit message and push the current project branch to `origin`. Verify the remote targets the repository above.
- Never force-push, rewrite existing history, or discard work to resolve a push failure. Report authentication, network, or branch conflicts if they prevent completion.
- This applies to work performed in response to user requests, not background monitoring of independently edited files. File-free answers do not require a commit.
